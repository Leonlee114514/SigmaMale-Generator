# 互联网 slop 视频 · 标准预制剪辑模版调研

> 调研对象：TikTok / Reels / Shorts 上的 brainrot / slop 短视频（含 sigma、gigachad 类）
> 调研目的：为 `SigmaMaleGenerator` 的"自动剪辑"功能提供可落地的模板清单
> 落地形态：全部实现为 ffmpeg 滤镜链，本机 ffmpeg 8.1.1 逐条实测通过（19/19）

---

## 一、结论先行

slop 的"味道"不来自某一个特效，而来自 **四层叠加**：

| 层 | 作用 | 常见手段 |
|---|---|---|
| 1. 节奏层 | 让人停不下来 | 曲线变速（卡点）、Boomerang、倒放 |
| 2. 构图层 | 适配竖屏 + 制造"廉价感" | 9:16 模糊填充、正方形黑边、镜像 |
| 3. 质感层 | 一眼认出是"slop" | 高对比调色、VHS 噪点、闪白、抖动 |
| 4. 故障层 | punchline 时炸一下 | RGB 通道分离（全片仅 1 次） |

**关键认知：这些效果单独看都很土，堆在一起才是 slop。** 单纯加一个"曲线变速"不会像 slop，必须同时叠构图错位和廉价质感。

## 二、节奏参数（从公开剪辑拆解中提炼）

| 项目 | 标准值 | 说明 |
|---|---|---|
| 总时长 | 15–30 秒 | 超过 30s 完播率断崖 |
| 原始素材 | 20–40 秒 | 再修剪 + 变速压缩到目标时长 |
| 梗图插入 | 每 3–5 秒一次，每次 **1–3 帧** | 短到几乎看不清，制造"信息轰炸" |
| 关键词缩放 | 每 5 秒 1 次 | 配合重音词 |
| 画面抖动 | 仅高潮时刻 | 用多了会晕，反而掉完播 |
| RGB 故障 | **整片仅 1 次** | 放在最重要 punchline。这是稀缺性效果，用两次就废了 |
| 背景乐音量 | 15–25%（相对人声） | 人声必须始终清晰 |
| 变速范围 | 上游加速至 **10x**，下游减速至 **0.1x** | 剪映/CapCut 速度曲线的官方上限 |
| 曲线锚点 | 首尾各 1 个 + 强调点 1 个 | 锚点越多越不可控 |
| 导出规格 | 9:16 / 30fps / 字幕烧录 | 字幕必须烧录，平台不会渲染你的 srt |

## 三、用户特别问到的两类

### 3.1 曲线变速（Speed Ramp）

剪映/CapCut 的"速度曲线"语义：**曲线图上半区 = 加速（最高 10x），下半区 = 减速（最低 0.1x）**。

ffmpeg 的对应实现是 `setpts`：

| 倍率 | 写法 | 效果 |
|---|---|---|
| 2 倍速 | `setpts=PTS/2` | 乘数 < 1 → 加速 |
| 0.5 倍速 | `setpts=PTS*2` | 乘数 > 1 → 减速 |

**三段式（最常用，即"快入 → 慢放高潮 → 快出"）：**

```
setpts=if(lt(T,1.4),PTS/3,
       if(lt(T,2.6),0.4667+(PTS-1.4)/0.4,
                    3.4667+(PTS-2.6)/3))
```

实测：4.00s 素材 → 6.43s（前段 3x 快、中段 0.4x 慢、后段 3x 快）。

**平滑正弦式（无硬切感，速度连续变化）：**

```
setpts=PTS*(1.0+0.8*sin(2*PI*T/1.0))
```

实测：4.00s 素材 → 5.90s，速度在 0.56x ~ 5x 之间往复。

**慢动作要丝滑必须补帧**，否则 30fps 素材放慢后会一格一格跳：

```
setpts=PTS*2,minterpolate='mi_mode=mci:mc_mode=aobmc:vsbmc=1:me_mode=bidir:search_param=32:fps=60'
```

实测：4.00s 素材 → 7.88s / 60fps。

### 3.2 正方 + 倒放

**正方**：把横屏素材放进正方形画布。两种做法——

- 模糊填充（推荐，slop 最常见）：自身放大 + 高斯模糊当背景，无黑边
  ```
  split=2[bg][fg];
  [bg]scale=1080:1080:force_original_aspect_ratio=increase,crop=1080:1080,gblur=sigma=28[bgb];
  [fg]scale=1080:-2[fgs];
  [bgb][fgs]overlay=(W-w)/2:(H-h)/2
  ```
- 黑边留白：`scale=1080:1080:force_original_aspect_ratio=decrease,pad=...`（更"廉价"，也有用）

**倒放**：`reverse` 滤镜。注意它**必须把整段解码进内存**，所以：
- 素材 ≤ 10 秒
- 要求动作有明确起点终点（否则倒放看不出"倒"）
- 素材里不能有文字（倒放后文字会变乱码，这是很多人踩的坑）

**Boomerang（正放 → 倒放，来回弹）**：
```
split=2[a][b];[b]reverse[bv];[a][bv]concat=n=2:v=1:a=0
```

**"正方 + 倒放"组合**（用户明确问到的）：两者可以串联，实测通过
```
reverse,<正方滤镜链>
```
关键顺序：**先倒放再改构图**。反过来的话倒放要处理更大的画布，内存翻倍。

## 四、其余标准模板

| 模板 | 滤镜链 | 用途 |
|---|---|---|
| 恒定变速 | `setpts=PTS*0.5` | 整体提速，压缩时长 |
| 镜像 | `hflip` / `vflip` | 规避版权检测 + "诡异感" |
| 镜像拼接 | `split=2[a][b];[b]hflip[bv];[a][bv]hstack` | 画面翻倍，视觉冲击 |
| 抖动 | `crop=iw-16:ih-16:X:Y,setsar=1` | punchline 时炸一下 |
| RGB 分离 | 三通道抽取 + 错位 + `blend=addition` | 全片仅 1 次 |
| 闪白 | `eq=brightness=...:eval=frame` | 踩节拍点 |
| 高对比调色 | `curves=preset=strong_contrast,eq=contrast=1.12` | sigma 味 |
| 黑白 chad | `hue=s=0,eq=contrast=1.55,unsharp` | gigachad 味 |
| VHS 质感 | `eq=saturation=1.35,tblend=all_mode=average,noise=alls=12` | 廉价感 |
| 9:16 竖屏 | 同"正方"，改尺寸为 1080x1920 | 上平台前的最后一步 |

## 五、本机 ffmpeg 的四个坑（实测踩过，全部已规避）

1. **`setpts` 表达式里的 `-` 会解析失败。**
   `setpts=(T<1.4)*(PTS-1.4)` → `Missing ')'`。
   改写为 `PTS+-1.4` 即可。本机 ffmpeg 8.1.1 特有。

2. **函数调用内的逗号会被当作滤镜分隔符。**
   `setpts=if(lt(T,1.4),A,B)` → `No such filter: '1.4)'`。
   必须转义：`if(lt(T\,1.4)\,A\,B)`。

3. **`crop` 的 x/y 表达式不能加单引号。**
   `crop=704:1264:'8+8*sin(n)':'...'` → 0 字节输出（**静默失败**，不报错）。
   去掉引号即可。

4. **滤镜链里不能把输出尺寸写死。**
   源是 720x1280 却写 `crop=1080:1920` → `Invalid too big or non positive size`
   → 0 字节输出。应该用 `iw`/`ih` 相对表达式。

> 坑 3 和坑 4 的共同特征是 **0 字节输出 + 非零退出码**，而测试脚本若只检查
> "文件存在"就会误判为通过。所以测试必须同时校验 **文件大小 > 1KB**。

## 六、落地建议：自动剪辑的判定逻辑

要让"自动剪辑"真的自动，需要从画面里抽事件信号：

| 信号 | 检测方式 | 触发的模板 |
|---|---|---|
| 人脸出现/消失 | MediaPipe FaceLandmarker | 切 sigma 构图 |
| 张嘴（说话重音） | blendshape `jawOpen` | 闪白 + 抖动 |
| 动作速度峰值 | 手腕关键点位移 | 曲线变速的慢放锚点 |
| 突然静止 | 关键点位移趋零 | 插入梗图/反打 |
| 整段高潮（识别不可靠） | 用音量包络代替 | RGB 故障 |

**最可靠的"卡点"信号其实是音量包络**，不是视觉。视觉动作识别误报率高，
而音轨的峰值检测又准又便宜 —— 建议以音频峰为主、视觉为辅。
